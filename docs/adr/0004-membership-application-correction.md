# 更正申请以学号+手机号匹配覆盖原记录

招新申请原本对同一学号直接 409 拒绝（ADR 未记录，由 `4330a2b` 引入的唯一索引实现）。实际上学生填错手机号、自我介绍等情况需要更正渠道，全部转人工对招新负责人是持续负担。我们改为：学生以**相同学号 + 相同手机号**再次提交时视为**更正申请**，用新资料覆盖原记录；手机号不匹配则返回 409 提示"请使用相同的手机号或联系招新负责人"。

双因子（学号 + 手机号）而非仅学号，是因为学号格式 `202\d{9}` 可枚举，纯学号匹配会让任何人能篡改他人申请；手机号是学生自己持有的第二因子。这不是强认证（手机号可被熟人知道），但把攻击面从"知道学号即可"收窄到"同时知道学号和手机号"，与申请资料的敏感程度相称。

实现要点：覆盖保留原 `id` 并更新 `updatedAt`；每次更正写入一条更正操作记录（`operation = 'correct'`，记学号、客户端 IP、时间，**不记手机号、不存被覆盖的旧值**——避免个人资料在系统里复制两份，与删除操作记录的轻量风格一致）。前端不做动态"是否已提交"查询（避免学号探测接口），只在表单顶部加静态提醒。

被拒绝的替代方案：① 纯学号覆盖（安全问题如上）；② 维持 409 拒绝 + 人工更正（负责人负担）；③ 动态 exists 接口 + 前端提醒（引入学号探测 oracle）。本决定影响数据库迁移、操作记录表结构和公开 API 行为，回退需要数据迁移，故记录。
