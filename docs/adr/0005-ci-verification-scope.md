# CI/CD 自动化门禁范围与单流水线防呆设计决策

面对端到端浏览器测试对 UI 文案与布局微调高度敏感、频繁导致 CI 假阳性爆红的问题，决定从 GitHub Actions CI 中彻底移除 Playwright 浏览器端到端测试，将 CI 严格定位于「工程与服务可用性烟囱防护门禁」。CI 仅保留以下确定性核心检查：依赖锁文件有效性、Astro 前端构建产物同步性、敏感凭证与文件防误提交扫描、静态源码语法与图片死链检查、Python 编译与后端 API 接口测试。浏览器视觉排版与交互细节交由开发者在手机与桌面浏览器人工验收，以换取秒级稳定反馈并消除无意义的阻断性误报。

同时，鉴于单人维护（Solo DevOps）无同行代码审查（Code Review）与独立测试团队兜底的现状，决定将原本独立的 CI（代码检查）与 CD（Docker 镜像构建推送）合并为单一流水线（`pipeline.yml`）。发版阶段的 Docker 构建严格依赖门禁阶段成功（`needs: verify`）；仅当版本 Tag（`v*`）推送或显式手动触发且门禁全绿时方可执行镜像构建，若任一检查未通过立即硬性熔断，从工程流水线上杜绝将缺陷代码打包为镜像推向生产。
