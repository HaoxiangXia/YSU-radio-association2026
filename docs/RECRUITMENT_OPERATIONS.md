# 招新日常运行说明

本文面向招新负责人和后续接交人员。日常工作通过网页完成，不要求理解 FastAPI、SQLite 或服务器命令。

## 登录

1. 打开网站页脚的“招新负责人入口”。
2. 输入负责人用户名和密码。
3. 私人设备可选择“保持登录 7 天”；公共电脑不要勾选，操作完成后点击“退出登录”。

负责人账号保存在服务器环境变量 `RECRUITMENT_OFFICER_ACCOUNTS` 中，密码只接受 PBKDF2 哈希。首次配置或更换密码时，在可信电脑交互运行：

```bash
cd backend && uv run python ../scripts/hash-password.py
```

将生成的哈希交给服务器维护者写入 `/etc/radio-association/app.env`。不要通过聊天、Git、截图或普通文档传递明文密码、JWT 密钥或完整环境文件。

## 开放入会申请

1. 登录后进入“招新设置与录取结果”。
2. 填写招新周期、开始时间、截止时间、资料保留期限、通知和联系方式。
3. 核对个人信息处理说明和香港服务器存储说明。
4. 更新学院、年级选项，每行一项。
5. 打开“开放入会申请”，点击“检查并保存设置”，核对变更摘要后确认。
6. 使用普通浏览器窗口实际提交一份测试资料，确认后台能看到后删除该测试记录。

系统只有在开关开启且当前时间处于起止时间内时才接受申请。正式开放前，个人信息处理说明、香港存储说明、负责人联系方式和保留期限必须由社团实际负责人确认。

## 处理入会申请

- 列表支持姓名、学号和学院搜索，以及学院、年级筛选。
- “导出 CSV”会导出当前筛选条件下的全部结果，并防止表格公式注入。
- 删除入会申请不可撤销。删除前先确认记录和申请人请求，正式数据操作前应确认最近备份正常。
- 不要把导出的 CSV 上传到公开网盘、群文件或 Git 仓库；使用完成后按社团确定的保留期限清理。

## 发布录取结果

按以下顺序操作，不要跳步：

1. 在“招新设置与录取结果”中先关闭“开放录取查询”并保存。
2. 下载标准 Excel 模板。
3. 模板第 2 行的“张三”是格式示例，填写真实名单前必须删除或完整替换，不能把示例行一起发布。
4. 只填写“录取名单”工作表的五列：姓名、学号、申请手机号、录取部门、录取状态。
5. 上传 `.xlsx`，点击“校验并预览”。文件不得超过 2 MiB，不得包含公式、宏或外部链接。
6. 检查总数、已录取数、未录取数、错误行和少量脱敏预览；总数必须等于准备发布的实际人数，预览中不得残留“张三”示例。
7. 校验无误后点击“确认发布此名单”。系统会保留旧名单备份，但录取查询仍保持关闭。
8. 用一条测试记录核对学号和申请手机号均匹配后才能查询。
9. 返回上方设置，开启“开放录取查询”并保存。
10. 使用普通浏览器分别测试正确手机号和错误手机号，确认只返回本人的必要结果。

关闭录取查询不会删除名单。替换名单时系统要求先关闭查询，以免申请人在更新过程中读到不一致结果。

## 结束本次招新

1. 关闭入会申请并保存，确认普通页面不能继续提交。
2. 需要时导出最终申请资料，保存到社团批准的受限位置。
3. 录取查询使用结束后关闭查询。
4. 到达资料保留期限前，由负责人确认备份、导出和删除范围；数据库恢复、批量删除和销毁属于高影响操作，必须由负责人明确批准。

## 备份和故障

日常自动备份由服务器定时任务完成。负责人发现以下情况时停止继续操作并联系维护者：

- 页面提示配置保存失败、名单发布失败或名单校验失败；
- 登录反复失效、出现未知账号或异常申请；
- 网站出现 500 错误、数据数量异常或误删；
- 服务器、域名或证书告警。

维护者使用 `radioctl backup/status/rollback/restore` 处理；不要直接复制运行中的 SQLite 文件，不要在生产环境运行 `scripts/init-db.js`，也不要删除数据库文件来“重置”问题。
